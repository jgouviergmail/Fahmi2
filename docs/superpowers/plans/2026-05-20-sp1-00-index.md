## Pourquoi 4 plans numérotés

Le SP1 est un **renommage/scission transverse** (`ProjectSettings → GenerationSettings`,
`Project` réduit à nom + emplacement). Un tel changement traverse domaine →
persistance → application → UI : il ne peut pas être livré « par couche » sans casser
la compilation. On le découpe donc en tranches **cohérentes**, chacune laissant
`pytest` / `ruff` / `mypy` **au vert** et l'application **fonctionnelle**, en suivant
la convention de plans numérotés déjà en place dans le dépôt.

| Plan | Titre | État final |
|------|-------|-----------|
| **01** | Refonte du modèle + persistance + migration | Modèle scindé ; **génération identique** ; UI mono-fenêtre actuelle conservée mais branchée sur le nouveau modèle |
| **02** | Coquille à onglets (abstraction fonctionnalité) | App à **2 onglets** (Génération = cockpit déplacé ; Pédagogie = *stub*) ; `RunController → GenerationController` |
| **03** | Réglages master-detail + création minimale | « Nouveau projet » = nom + emplacement ; réglages Génération dans une vue master-detail réutilisable ; état `generation = None` |
| **04** | Câblage final, docs, vérifications | `app_main` finalisé, `docs/` + `README.md` + `CLAUDE.md` à jour, passes qualité finales |

Chaque plan se termine par une **passe qualité obligatoire** (`pytest`, `ruff check .`,
`mypy src tests`) — exigence permanente du projet.

## Structure de fichiers cible (vue d'ensemble SP1)

**Domaine**
- `src/fahmi2/domain/generation.py` *(créé)* — `ParallelismConfig`, `GenerationSettings`,
  constante `GENERATION_WORKSPACE_SUBDIR`.
- `src/fahmi2/domain/project.py` *(modifié)* — `Project` minimal (nom + emplacement +
  `generation`).
- `src/fahmi2/domain/run.py` *(modifié)* — `settings_snapshot: GenerationSettings`.

**Persistance**
- `src/fahmi2/infra/storage/sqlite_state.py` *(modifié)* — (dé)sérialisation v2,
  migration lenient v1→v2, `_row_to_project` / `upsert_project` / SELECTs.

**Application**
- `src/fahmi2/app/project_service.py` *(modifié)* — `create_project(name, workspace_folder, generation)`.
- `src/fahmi2/app/run_orchestrator.py` *(modifié)* — lit `project.generation`,
  reconstruit le `Project` minimal.

**UI** *(plans 02–03)*
- `src/fahmi2/ui/features/` *(créé)* — `feature.py` (`FeatureId`, `FeatureTab`),
  `registry.py` (`FeatureRegistry`), `generation_tab.py`, `pedagogy_tab.py`.
- `src/fahmi2/ui/generation_controller.py` *(renommé depuis `run_controller.py`)*.
- `src/fahmi2/ui/main_window.py` *(modifié)* — zone centrale en `QTabWidget`.
- `src/fahmi2/ui/widgets/settings_view.py` *(créé)* — composant master-detail réutilisable.
- `src/fahmi2/ui/dialogs/new_project_dialog.py` *(modifié)* — minimal (nom + emplacement).
- `src/fahmi2/ui/dialogs/generation_settings_view.py` *(créé)* — réglages Génération.
- `src/fahmi2/ui/app_main.py` *(modifié)* — câblage registre + onglets + nouveaux flux.

**Tests**
- `tests/conftest.py` *(modifié)* — `make_generation_settings` (+ `make_project`).
- ~21 fichiers de tests à adapter au nouveau modèle (énumérés dans chaque plan).

## Traçabilité (exigences du chapeau couvertes par le SP1)

R1 (onglets) → Plan 02 · R2 (`Project` minimal) → Plan 01 · R3 (`GenerationSettings`) →
Plan 01 · R4 (migration) → Plan 01 · R5 (abstraction onglet + stub) → Plan 02 ·
R6 (workspace par fonctionnalité) → Plan 01 · R7 (réglages master-detail) → Plan 03.
